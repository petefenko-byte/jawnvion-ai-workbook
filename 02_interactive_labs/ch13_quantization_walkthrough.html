Model Quantization

Shrink models 4–8× with minimal quality loss. Master precision formats, PTQ vs QAT, GPTQ, AWQ, GGUF, and bitsandbytes for efficient inference.

FP32 → INT4 PTQ / QAT GPTQ AWQ GGUF bitsandbytes
13.1 · Motivation

The Size Problem

Modern LLMs are too large to run efficiently on commodity hardware — quantization is the primary tool for closing that gap.

28 GB
FP32 memory for a 7B model — won't fit on most GPUs
3.5 GB
INT4 memory for the same 7B model — fits on an 8GB GPU
8×
Max compression ratio (FP32 → INT4) with minimal perplexity loss
2–4×
Typical inference throughput improvement at INT8 vs FP32

PTQ — Post-Training Quantization

Quantize a trained model without retraining. Fast and cheap. Best quality when calibrated on a small representative dataset. Used by GPTQ, AWQ, and bitsandbytes.

QAT — Quantization-Aware Training

Simulate quantization during training so the model learns to be robust to it. Higher quality at low bit widths, but requires training compute. Common in mobile/edge deployment.

Dynamic vs Static Quantization

Static: calibrate scale factors offline from representative data. Dynamic: compute scale at runtime per-tensor. Static is faster; dynamic needs no calibration dataset.

13.4 · Quality vs Compression

Perplexity Degradation Curve

Lower perplexity = better quality. INT8 is near-lossless. INT4 with calibration (GPTQ/AWQ) stays close. Naive INT4 and below degrade quickly.

Perplexity vs Bits per Weight — Llama-class 7B model (illustrative)
Near-Lossless Zone

FP16, BF16, INT8 — perplexity within 2% of FP32 baseline. Safe for all production use cases.

Acceptable Zone

INT4 with GPTQ/AWQ calibration — 3–10% perplexity increase. Good for chat, summarization, general inference.

Degraded Zone

INT3 and below — significant degradation. Experimental only. May incohere on long-form generation.

13.5 · Quantization Methods

GPTQ · AWQ · GGUF · bitsandbytes

Each method has different trade-offs for quality, speed, hardware support, and ease of use.

GPTQ

Layer-wise Optimal Brain Quantization

Uses calibration data + Hessian-based weight compensation to minimize quantization error layer-by-layer. State-of-the-art INT4 quality.

Quality
88%
Speed
72%
Ease
65%
HW Flex
55%

Needs GPU for quant. Excellent for A100/H100 inference. Supported in vLLM, AutoGPTQ, HuggingFace.

AWQ

Activation-Aware Weight Quantization

Identifies salient weights via activation magnitude and preserves them at higher precision. Often outperforms GPTQ at INT4.

Quality
92%
Speed
80%
Ease
70%
HW Flex
62%

Faster than GPTQ to quantize. State of the art for INT4. Supported in llm-awq, vLLM, TGI.

GGUF

llama.cpp Format (CPU + GPU hybrid)

Quantized weights packed in a single portable file. Runs on CPU with optional GPU offload. The most portable format — works on MacBook, Raspberry Pi, servers.

Quality
82%
Speed
60%
Ease
90%
HW Flex
98%

Standard for local inference (Ollama, LM Studio, llama.cpp). Q4_K_M is the community sweet spot.

bitsandbytes

Load-Time INT8 / NF4 via HuggingFace

One-line load_in_8bit=True or load_in_4bit=True. LLM.int8() uses mixed-precision decomposition; NF4 (QLoRA) uses a normal-float quantile grid.

Easiest entry point. Great for QLoRA fine-tuning with NF4. Requires CUDA GPU. Slower than compiled GPTQ kernels.

13.6 · Implementation

Quantization Code Patterns

Copy-paste ready implementations for each method.

# bitsandbytes — easiest path to INT8 and NF4 (INT4) quantization
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
import torch

# ── INT8 (LLM.int8) ──────────────────────────────────────
bnb_int8_config = BitsAndBytesConfig(
    load_in_8bit=True,
    llm_int8_threshold=6.0,          # outlier threshold for mixed-precision
    llm_int8_skip_modules=["lm_head"], # keep final head in FP16
)

# ── NF4 / QLoRA (INT4) ───────────────────────────────────
bnb_nf4_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",       # NormalFloat4 grid — better than INT4
    bnb_4bit_use_double_quant=True, # quantize the scale factors too
    bnb_4bit_compute_dtype=torch.bfloat16,
)

model_id = "meta-llama/Meta-Llama-3-8B-Instruct"

model = AutoModelForCausalLM.from_pretrained(
    model_id,
    quantization_config=bnb_nf4_config,
    device_map="auto",    # spread across available GPUs automatically
    torch_dtype=torch.bfloat16,
)
tokenizer = AutoTokenizer.from_pretrained(model_id)

# Memory footprint check
print(f"Footprint: {model.get_memory_footprint() / 1e9:.2f} GB")

# QLoRA fine-tuning — NF4 base + LoRA adapters in BF16
from peft import get_peft_model, LoraConfig, prepare_model_for_kbit_training

model = prepare_model_for_kbit_training(model)
lora_config = LoraConfig(
    r=16, lora_alpha=32, target_modules=["q_proj", "v_proj"],
    lora_dropout=0.05, bias="none", task_type="CAUSAL_LM",
)
model = get_peft_model(model, lora_config)
model.print_trainable_parameters()
# trainable params: ~6.5M / total: ~8B  →  0.08% trained
# GPTQ — layer-wise optimal quantization with calibration data
# pip install auto-gptq optimum
from auto_gptq import AutoGPTQForCausalLM, BaseQuantizeConfig
from transformers import AutoTokenizer
from datasets import load_dataset

model_id = "meta-llama/Meta-Llama-3-8B"
output_dir = "./llama-3-8b-gptq-int4"

# ── Quantization config ──────────────────────────────────
quant_config = BaseQuantizeConfig(
    bits=4,             # INT4
    group_size=128,     # quantization group size (128 is standard)
    desc_act=False,    # activation ordering — False = faster inference
    damp_percent=0.01, # Hessian dampening for numerical stability
)

# ── Calibration dataset (128 samples typical) ────────────
tokenizer = AutoTokenizer.from_pretrained(model_id)
ds = load_dataset("wikitext", "wikitext-2-raw-v1", split="train")
calib_data = [
    tokenizer(row["text"], return_tensors="pt", max_length=2048, truncation=True)
    for row in ds.select(range(128))
    if len(row["text"].split()) > 50
]

# ── Load + quantize ──────────────────────────────────────
model = AutoGPTQForCausalLM.from_pretrained(model_id, quant_config)
model.quantize(calib_data)      # ~20 min on A100 for 8B model
model.save_quantized(output_dir, use_safetensors=True)
tokenizer.save_pretrained(output_dir)

# ── Load quantized model for inference ───────────────────
model = AutoGPTQForCausalLM.from_quantized(
    output_dir,
    device_map="auto",
    use_triton=False,   # True = faster but requires triton kernel
)
# AWQ — Activation-Aware Weight Quantization
# pip install autoawq
from awq import AutoAWQForCausalLM
from transformers import AutoTokenizer

model_id = "meta-llama/Meta-Llama-3-8B-Instruct"
output_dir = "./llama-3-8b-awq-int4"

# ── AWQ quantization config ──────────────────────────────
quant_config = {
    "zero_point": True,    # asymmetric quantization
    "q_group_size": 128,  # group size — 128 is optimal for quality/speed
    "w_bit": 4,            # INT4 weights
    "version": "GEMM",    # GEMM = faster; GEMV = better for batch=1
}

model = AutoAWQForCausalLM.from_pretrained(model_id, safetensors=True)
tokenizer = AutoTokenizer.from_pretrained(model_id, trust_remote_code=True)

# Quantize — uses activation statistics to find salient weights
model.quantize(tokenizer, quant_config=quant_config)

model.save_quantized(output_dir)
tokenizer.save_pretrained(output_dir)

# ── Load AWQ for vLLM inference ───────────────────────────
from vllm import LLM, SamplingParams

llm = LLM(
    model=output_dir,
    quantization="awq",          # tell vLLM the quant format
    dtype="auto",
    max_model_len=4096,
    gpu_memory_utilization=0.9,
)

outputs = llm.generate(
    ["Explain quantization in one paragraph:"],
    SamplingParams(temperature=0.7, max_tokens=200),
)
print(outputs[0].outputs[0].text)

# benchmark_quant.py — compare perplexity and throughput across formats
import torch, time, math
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from datasets import load_dataset

def measure_perplexity(model, tokenizer, num_samples=20) -> float:
    model.eval()
    ds = load_dataset("wikitext", "wikitext-2-raw-v1", split="test")
    total_loss, total_tokens = 0.0, 0

    with torch.no_grad():
        for row in ds.select(range(num_samples)):
            enc = tokenizer(row["text"], return_tensors="pt",
                             max_length=512, truncation=True).to(model.device)
            if enc.input_ids.shape[1] < 10: continue
            out = model(**enc, labels=enc.input_ids)
            total_loss   += out.loss.item() * enc.input_ids.shape[1]
            total_tokens += enc.input_ids.shape[1]

    return math.exp(total_loss / total_tokens)

def measure_throughput(model, tokenizer, n=10) -> float:
    prompt = tokenizer("The future of AI is", return_tensors="pt").to(model.device)
    t0 = time.perf_counter()
    with torch.no_grad():
        for _ in range(n):
            model.generate(**prompt, max_new_tokens=50, do_sample=False)
    elapsed = time.perf_counter() - t0
    return (n * 50) / elapsed  # tokens / second

# ── Run benchmark for NF4 ────────────────────────────────
model_id = "meta-llama/Meta-Llama-3-8B"
configs = {
    "FP16": None,
    "INT8": BitsAndBytesConfig(load_in_8bit=True),
    "NF4":  BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                                  bnb_4bit_compute_dtype=torch.bfloat16),
}
tokenizer = AutoTokenizer.from_pretrained(model_id)
for name, cfg in configs.items():
    model = AutoModelForCausalLM.from_pretrained(
        model_id, quantization_config=cfg,
        device_map="auto", torch_dtype=torch.float16,
    )
    ppl = measure_perplexity(model, tokenizer)
    tps = measure_throughput(model, tokenizer)
    mem = model.get_memory_footprint() / 1e9
    print(f"{name:6s}  PPL={ppl:.2f}  {tps:.1f} tok/s  {mem:.1f} GB")
13.7 · Quick Reference

Quantization Cheat Sheet

📐 Precision Memory

  • FP32: 4 bytes/param → 7B = 28 GB
  • FP16/BF16: 2 bytes → 7B = 14 GB
  • INT8: 1 byte → 7B = 7 GB
  • INT4: 0.5 bytes → 7B = 3.5 GB
  • Add ~20% overhead for KV cache + activations

🎯 Format Decision

  • Training: BF16 (better range than FP16)
  • Inference (server): INT8 or AWQ INT4
  • Fine-tuning cheap: NF4 + QLoRA (bitsandbytes)
  • Local / portable: GGUF Q4_K_M (Ollama)
  • Max quality INT4: AWQ > GPTQ > NF4

⚖️ Quality vs Speed

  • FP16 → INT8: ~0–2% perplexity, 1.5–2× throughput
  • INT8 → INT4 (AWQ): ~5–8% perplexity, 2–3× throughput
  • INT4 → INT3: ~20%+ perplexity — avoid
  • Group size 128: best quality/speed balance

🔧 GGUF Q-Levels

  • Q2_K: Smallest, noticeable quality loss
  • Q4_0: Fast, slight quality loss
  • Q4_K_M: ← Community recommended sweet spot
  • Q5_K_M: Better quality, ~20% larger
  • Q8_0: Near-lossless, use for benchmarking

⚡ PTQ vs QAT

  • PTQ: No retraining, fast, slight quality loss
  • QAT: Requires training, better quality at low bits
  • When to QAT: INT4 or below, edge/mobile deployment
  • PTQ tools: GPTQ, AWQ, bitsandbytes, llama.cpp

🚀 Serving Stack

  • Local dev: Ollama (zero config)
  • Production GPU: vLLM + AWQ or GPTQ
  • HuggingFace: TGI with bitsandbytes
  • Fine-tune budget: bitsandbytes NF4 + PEFT
  • Edge: llama.cpp Q4_K_M or ExecuTorch
