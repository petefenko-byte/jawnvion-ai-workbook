The Problem
RLHF Is Complex — DPO Simplifies It

Reinforcement Learning from Human Feedback (RLHF) works but requires training three separate models and fighting PPO instability. DPO collapses the entire pipeline into one supervised loss.

❌ RLHF Pipeline
1
SFT Model — supervised fine-tune on demonstrations
2
Reward Model — train a separate classifier on preference pairs
3
PPO Loop — RL policy update against reward model + KL penalty
4
Reference Model — frozen copy to anchor KL divergence
4 models in memory · PPO instability · reward hacking risk
✅ DPO Pipeline
1
SFT Model — supervised fine-tune on demonstrations
2
Preference Data — collect chosen / rejected pairs per prompt
3
DPO Loss — optimize directly on pairs (no reward model needed)
2 models in memory · stable training · no reward hacking

Math
The DPO Loss Function

DPO derives an implicit reward signal directly from the policy. The key insight: the optimal policy under a KL-constrained RL objective has a closed form — no RL loop required.

LDPO(πθ) = −𝔼(x,yw,yl) [log σ ( β log πθ(yw|x) / πref(yw|x) − β log πθ(yl|x) / πref(yl|x) )]
β (beta)Controls how much the policy can deviate from the reference. Higher β → stays closer to SFT model.
y_w (chosen)The preferred response. DPO increases its log-probability relative to the reference policy.
y_l (rejected)The dispreferred response. DPO decreases its log-probability relative to reference.
π_refThe frozen SFT model. Acts as the KL anchor — preventing catastrophic forgetting.
β controls the KL penalty — drag to see how it shapes the reward margin
β = 0.10 Low β = aggressive · High β = conservative
Training Loop
Animated DPO Training Pass

Each training step forward-passes both the active policy and the frozen reference model, then uses the log-ratio difference as an implicit reward signal.

Data Format
DPO Dataset Schema

TRL's DPOTrainer expects a dataset with three fields per example. You can also use conversation-style chat format.

# Standard format (text fields) { "prompt": "What is the capital of France?", "chosen": "The capital of France is Paris, which has been\n the country's capital since the 10th century.", "rejected": "France is a country in Europe." } # Chat format (messages list) { "prompt": [{ "role": "user", "content": "Explain gravity" }], "chosen": [{ "role": "assistant", "content": "Gravity is the force that..." }], "rejected": [{ "role": "assistant", "content": "It's complicated physics." }] } # Popular open DPO datasets: # HuggingFaceH4/ultrafeedback_binarized (64K pairs) # Anthropic/hh-rlhf (170K pairs) # tatsu-lab/alpaca_farm (20K pairs)

from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model
from trl import DPOConfig, DPOTrainer

# Load SFT-fine-tuned model as starting point
model = AutoModelForCausalLM.from_pretrained("./sft-checkpoint")
tokenizer = AutoTokenizer.from_pretrained("./sft-checkpoint")

# DPOTrainer creates the reference model automatically
# (frozen copy of model at initialization)

# Optional: use LoRA to keep memory low
peft_config = LoraConfig(
    r=16, lora_alpha=32,
    target_modules=["q_proj", "v_proj"],
    bias="none", task_type="CAUSAL_LM"
)
from datasets import load_dataset

# Load a standard DPO preference dataset
dataset = load_dataset(
    "HuggingFaceH4/ultrafeedback_binarized",
    split="train_prefs"
)

# The dataset already has 'prompt', 'chosen', 'rejected' cols
# If building your own, structure it the same way:
custom = Dataset.from_list([
    {
        "prompt":   "What is 2+2?",
        "chosen":   "2+2 equals 4.",
        "rejected": "Math is hard."
    },
    # ... more examples
])

# Tokenizer padding side must be LEFT for causal LMs
tokenizer.padding_side = "left"
dpo_config = DPOConfig(
    beta=0.1,                   # KL penalty coefficient
    output_dir="./dpo-output",
    num_train_epochs=1,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=5e-7,         # much lower than SFT
    warmup_ratio=0.1,
    fp16=True,
    logging_steps=10,
    loss_type="sigmoid",        # original DPO loss
    max_length=1024,
    max_prompt_length=512,
)

trainer = DPOTrainer(
    model=model,
    ref_model=None,             # auto-created if None
    args=dpo_config,
    train_dataset=dataset,
    tokenizer=tokenizer,
    peft_config=peft_config,   # optional: LoRA adapters
)
trainer.train()
# Key DPO training metrics to monitor:

# rewards/chosen  — should INCREASE over training
# rewards/rejected — should DECREASE over training
# rewards/margins — chosen - rejected (key signal)
# logps/chosen   — log probability of chosen response
# logps/rejected  — log probability of rejected response

# Healthy training looks like:
# ✓ margins steadily increasing
# ✓ chosen logps increasing
# ✓ rejected logps decreasing
# ✗ If logps/chosen drops too: beta too high, lower it
# ✗ If margins plateau quickly: dataset quality low

Quick Reference
DPO Cheat Sheet
β Tuning Guide
β = 0.01–0.05 — aggressive, may collapse
β = 0.1 — default, good starting point
β = 0.5 — conservative, stays near SFT
β = 1.0+ — very conservative, small updates
Monitor rewards/margins to tune β
DPO Variants
sigmoid — original DPO loss (Rafailov 2023)
hinge — margin-based, ignores easy pairs
ipo — IPO, avoids overfitting to pairs
kto — KTO, uses binary signal (good/bad)
cpo — CPO, no reference model needed
Data Quality Signals
Margin: chosen must be clearly better
Diversity: varied prompts, not repetitive
Avoid: pairs where diff is trivial (length)
Label noise: major failure mode, audit data
Quantity: 1K–100K depending on domain
Key Metrics
rewards/margins — primary training signal
logps/chosen — should increase
logps/rejected — should decrease
win_rate — % beats SFT baseline
MT-Bench — multi-turn dialogue quality
