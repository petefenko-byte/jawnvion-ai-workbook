The Problem

Three Ways Models Fail in Silence

A model that was 94% accurate at launch may be 71% accurate six months later — and your loss function will never tell you.

📉

Data Drift

The distribution of inputs shifts away from training data. Users start writing differently, a new product is added, a sensor drifts. The model answers on data it's never seen.

🌀

Concept Drift

The relationship between inputs and labels changes. "Urgent" emails used to be from the CEO — now they're phishing. The world changed; your model's priors didn't.

💥

Infrastructure Failure

Memory leak after 72 hours. GPU OOM on long inputs. Latency spikes during traffic bursts. These are purely operational — caught by infrastructure metrics, not model metrics.

Tool Landscape

Monitoring Stack Options

No single tool covers everything. Most production ML systems combine infrastructure monitoring (Prometheus/Grafana) with ML-specific observability (Evidently, Arize, or W&B).

Prometheus + Grafana

The open-source standard for infrastructure monitoring. Prometheus scrapes metrics from your FastAPI service via the /metrics endpoint; Grafana renders dashboards and fires alerts.

Open source Infrastructure Self-hosted PromQL
✓ Industry standard — massive community, integrations everywhere
✓ Free forever; runs in your infra with full data control
✓ Best for latency, throughput, error rate, GPU utilization
✗ No built-in drift detection or prediction monitoring
✗ PromQL learning curve; dashboards require manual setup
FastAPI + prometheus-fastapi-instrumentator
from fastapi import FastAPI
from prometheus_fastapi_instrumentator import Instrumentator
from prometheus_client import Histogram, Counter, Gauge

app = FastAPI()

# Auto-instrument: latency, request count, response size
Instrumentator().instrument(app).expose(app)

# Custom ML metrics
CONFIDENCE = Histogram(
    "model_confidence",
    "Model output confidence scores",
    buckets=[0.5,0.6,0.7,0.8,0.9,0.95,1.0]
)
DRIFT_SCORE = Gauge(
    "feature_psi_score",
    "Population stability index by feature",
    ["feature_name"]
)
PREDICTION_COUNT = Counter(
    "predictions_total",
    "Total predictions by label",
    ["label"]
)

@app.post("/predict")
async def predict(req: PredictRequest):
    result = model(req.text)
    label, score = result[0]["label"], result[0]["score"]
    CONFIDENCE.observe(score)         # histogram bucket
    PREDICTION_COUNT.labels(label).inc()
    return {"label": label, "score": score}
# Metrics at: GET /metrics (Prometheus scrapes here)

Evidently AI

Purpose-built for ML monitoring. Computes data drift, target drift, data quality, and regression/classification performance metrics — all as interactive HTML reports or JSON snapshots.

Open source ML-native Drift detection Reports + UI
✓ Best-in-class drift detection: PSI, KS test, Wasserstein
✓ Beautiful HTML reports shareable with stakeholders
✓ Cloud platform (Evidently Cloud) for continuous monitoring
✗ No infrastructure metrics — pair with Prometheus
✗ Needs reference dataset stored and accessible
Evidently drift report
import pandas as pd
from evidently import ColumnMapping
from evidently.report import Report
from evidently.metric_preset import (
    DataDriftPreset, ClassificationPreset
)

# Load reference (training) + current (production) data
reference = pd.read_parquet("reference.parquet")
current   = pd.read_parquet("production_last_7d.parquet")

column_mapping = ColumnMapping(
    target="label",
    prediction="prediction",
    text_features=["text"]
)

# Build report — drift + classification performance
report = Report(metrics=[
    DataDriftPreset(),
    ClassificationPreset()
])
report.run(
    reference_data=reference,
    current_data=current,
    column_mapping=column_mapping
)

report.save_html("weekly_drift_report.html")
result = report.as_dict()

# Check PSI for each feature
for metric in result["metrics"]:

Weights & Biases (W&B)

Originally an experiment tracker, W&B now covers production monitoring via Tables, Artifacts, and the new Model Registry. Best for teams already using W&B for training — one platform end-to-end.

SaaS Experiment + prod Model registry Free tier
✓ One platform from training → evaluation → production
✓ Beautiful dashboards, collaborative — great for teams
✓ Artifact versioning links production model to training run
✗ SaaS — data leaves your infra (enterprise plan for private)
✗ Drift detection is less mature than Evidently
W&B production logging
import wandb
from fastapi import BackgroundTasks

# Initialize once at startup (in lifespan)
run = wandb.init(
    project="ekos-production",
    name="inference-api-prod",
    job_type="production",
    resume="allow"
)
prediction_table = wandb.Table(
    columns=["text", "label", "score", "latency_ms"]
)

async def log_prediction(text, label, score, latency):
    # Logged as background task — doesn't slow response
    prediction_table.add_data(text, label, score, latency)
    wandb.log({
        "inference/latency_ms": latency,
        "inference/confidence": score,
        "inference/label_positive": 1 if label=="POSITIVE" else 0
    })

@app.post("/predict")
async def predict(req, bg: BackgroundTasks):
    result = model(req.text)
    bg.add_task(log_prediction,
        req.text, result["label"],
        result["score"], result["latency_ms"])
    return result

Arize AI

Enterprise ML observability platform. Designed for large-scale production: automatic drift alerts, explainability via SHAP, embedding drift for NLP, and root-cause analysis tied to data slices.

Enterprise SaaS Embedding drift SHAP explainability Paid
✓ Embedding drift — critical for LLM and NLP model monitoring
✓ Automatic root-cause surfacing — which data slice degraded
✓ Works at massive scale; used by Fortune 500 ML teams
✗ Expensive — pricing by events logged
✗ Overkill for small/single-model deployments
Arize embedding drift logging
import arize

    )

Complete Monitoring Setup

End-to-end code for a production monitoring stack — structured logging, Prometheus metrics, scheduled drift checks, and a retraining trigger.

import structlog, uuid
from fastapi import Request
from starlette.middleware.base import BaseHTTPMiddleware

# Configure structlog — outputs JSON lines (ship to Datadog/Loki)
structlog.configure(
    processors=[
        structlog.processors.TimeStamper(fmt="iso"),
        structlog.stdlib.add_log_level,
        structlog.processors.JSONRenderer()
    ]
)
logger = structlog.get_logger()

class RequestLoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request: Request, call_next):
        req_id = str(uuid.uuid4())[:8]
        response = await call_next(request)
        logger.info(
            "request",
            request_id=req_id,
            method=request.method,
            path=request.url.path,
            status=response.status_code,
        )
        response.headers["X-Request-Id"] = req_id
        return response

# Structured log for each prediction:
async def log_inference(req_id, text, label, score, latency):
    logger.info(
        "inference",
        request_id=req_id,
        text_len=len(text),
        label=label,
        confidence=round(score, 4),
        latency_ms=latency,
        model_version="1.0.0",
    )

from prometheus_client import (
    Histogram, Counter, Gauge, generate_latest
)
from fastapi import Response

# ── Define metrics ────────────────────────────────
REQUEST_LATENCY = Histogram(
    "inference_latency_seconds",
    "End-to-end request latency",
    buckets=[.005,.01,.025,.05,.1,.25,.5,1,2.5]
)
PREDICTIONS = Counter(
    "predictions_total",
    "Predictions by label and model version",
    ["label", "model_version"]
)
CONFIDENCE = Histogram(
    "prediction_confidence",
    "Model output confidence 0-1",
    buckets=[.5,.6,.7,.75,.8,.85,.9,.95,.99]
)
PSI_SCORE = Gauge(
    "feature_psi_score",
    "Population Stability Index by feature",
    ["feature"]
)
MODEL_LOADED = Gauge("model_loaded", "1 if model is loaded")

# ── Expose metrics endpoint ───────────────────────
@app.get("/metrics")
async def metrics():
    return Response(
        generate_latest(),
        media_type="text/plain"
    )

# ── Instrument the predict route ──────────────────
@app.post("/predict")
async def predict(req):
    with REQUEST_LATENCY.time():
        result = model(req.text)
    label, score = result["label"], result["score"]
    PREDICTIONS.labels(label, "1.0.0").inc()
    CONFIDENCE.observe(score)
    return result

reference_df = pd.read_parquet("reference_data.parquet")

async def run_drift_check():
    # Pull last 24h of production predictions from DB
    current_df = await fetch_recent_predictions(hours=24)

    if len(current_df) < 100:
        logger.warning("drift_check_skipped", reason="insufficient data")
        return

    report = Report(metrics=[DataDriftPreset()])
    report.run(
        reference_data=reference_df,
        current_data=current_df
    )
    result = report.as_dict()

    for metric in result["metrics"]:
        r = metric.get("result", {})
        feature = r.get("column_name")
        psi     = r.get("drift_score", 0)

        if feature:
            PSI_SCORE.labels(feature).set(psi)  # → Prometheus
            if psi > 0.25:
                logger.warning("drift_detected", feature=feature, psi=psi)
                await alert_slack(f"Drift on {feature}: PSI={psi:.3f}")

# Run drift check every 6 hours
scheduler = AsyncIOScheduler()
scheduler.add_job(run_drift_check, "interval", hours=6)
scheduler.start()

from dataclasses import dataclass
from enum import Enum

class RetrainReason(str, Enum):
    DRIFT         = "data_drift"
    PERFORMANCE   = "performance_degradation"
    SCHEDULE      = "scheduled"
    MANUAL        = "manual_trigger"

@dataclass
class RetrainTrigger:
    reason: RetrainReason
    metric_name: str
    metric_value: float
    threshold: float

# ── Trigger evaluation logic ─────────────────────
RETRAIN_RULES = [
    ("psi_text_length",  "gt", 0.25, RetrainReason.DRIFT),
    ("avg_confidence",   "lt", 0.70, RetrainReason.PERFORMANCE),
    ("weekly_f1_score",  "lt", 0.88, RetrainReason.PERFORMANCE),
]

async def evaluate_retrain_triggers(metrics: dict):
    for name, op, threshold, reason in RETRAIN_RULES:
        val = metrics.get(name, 0)
        triggered = (op == "gt" and val > threshold) or \
                    (op == "lt" and val < threshold)
        if triggered:
            trigger = RetrainTrigger(
                reason=reason, metric_name=name,
                metric_value=val, threshold=threshold
            )
            await dispatch_retrain_job(trigger)
            logger.warning("retrain_triggered",
                reason=reason, metric=name, val=val)

async def dispatch_retrain_job(trigger: RetrainTrigger):
    # Push to your training pipeline (Airflow, Prefect, Modal)
    payload = {
        "trigger": trigger.reason,
        "base_model": "distilbert-base-uncased",
        "dataset_version": "latest",
        "notes": f"{trigger.metric_name}={trigger.metric_value:.3f}"
    }
    await post_to_training_api("/retrain", payload)

Quick Reference

Monitoring Cheat Sheet

4 Metric Layers

›Infrastructure — latency, throughput, error rate, CPU/GPU
›Model — confidence, label distribution, perplexity
›Data — PSI, KS test, feature distribution shift
›Business — downstream KPIs, human review rates, $impact

PSI Thresholds

›0 – 0.1 — No significant shift, monitor normally
›0.1 – 0.25 — Moderate drift, investigate features
›> 0.25 — Major drift — trigger retraining pipeline
›Run PSI on every numerical feature and embedding

Alert Cadence

›Latency P95 > 200ms for 1 min → PagerDuty
›Error rate > 5% for 2 min → Slack oncall
›Avg confidence < 0.70 for 5 min → retrain queue
›PSI > 0.25 on any feature → data team alert

Logging Rules

›Always structured JSON — ship to Loki, Datadog, CloudWatch
›Include: request_id, model_version, latency, label, confidence
›Never log raw PII — hash or truncate user text
›Log asynchronously (BackgroundTasks) — never block response

Retrain Triggers

›PSI > 0.25 on any feature (data drift)
›Avg confidence drops 5+ points vs baseline
›Labeled F1 drops below acceptance threshold
›Time-based: retrain monthly minimum regardless

Stack by Scale

›Solo / MVP — W&B free + structured logging
›Team / Production — Prometheus + Grafana + Evidently
›Enterprise — Arize or Fiddler for embedding + SHAP
›Always pair infra monitoring with ML-specific monitoring
