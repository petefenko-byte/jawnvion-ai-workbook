The Problem

Three Things That Break Without Eval

Training a model without evaluating it is like navigating without instruments — you feel confident until you're not.

🎯

No Direction

Without metrics you don't know if changes help or hurt. Loss goes down — but does the model actually answer better? Vibe checks don't scale to 10,000 examples.

📉

Silent Regressions

A new checkpoint improves one capability while silently breaking another. Automated eval suites catch this before you ship it.

🧪

No Reproducibility

If you can't measure it, you can't reproduce it. A reproducible eval harness lets you compare runs, share results, and build trust with stakeholders.

Core Metrics

Know Your Metric Families

The right metric depends on your task type. Classification, generation, and alignment each have their own vocabulary.

AccuracyFraction of correct predictions overallBalanced datasets only — misleading on skewed class distributions
PrecisionOf predicted positives, how many are actually positiveWhen false positives are costly (spam filter, fraud)
RecallOf actual positives, how many did we catchWhen false negatives are costly (cancer detection, safety)
F1Harmonic mean of precision and recallImbalanced classes — the go-to default for NLP classification
ROC-AUCArea under the receiver operating curve across all thresholdsBinary tasks where threshold-independence matters
MCCMatthews correlation — robust to class imbalanceHighly skewed datasets; single number that captures all four quadrants

BLEUN-gram precision vs. reference — modified for brevity penaltyMachine translation; fast, interpretable, but surface-level

METEORPrecision + recall with stemming, synonyms, and word orderTranslation; correlates better with human judgments than BLEU

MAUVEKL divergence between generated and reference text distributionsOpen-ended generation quality; coherence and diversity together

PerplexityGeometric mean of inverse token probabilities — lower = more fluentLanguage model training; domain adaptation; fluency checks

💡 ROUGE Limitations

ROUGE only measures surface n-gram overlap — "fast" and "quick" score zero despite being synonyms. BERTScore uses contextual embeddings to handle paraphrase. Use ROUGE as a fast proxy; use BERTScore or human eval for production decisions.

✅ Best Practices

Use rubrics, not just "which is better." Score 1–5 on specific criteria: accuracy, clarity, completeness. Ask the judge to explain before scoring.

⚠️ Position Bias

LLM judges tend to prefer whichever response is listed first. Always run pairwise comparisons in both orders and average the results.

🔁 Self-Evaluation

Avoid using the same model to judge its own outputs — it will rate itself higher. Use a separate, ideally stronger model as the judge.

Full Pipeline

Running a Complete Eval

Click any step to expand the detail, then check the code tabs below for working implementations.

1
Define Task & Metric
Choose your task type first: classification, summarization, code gen, or open-ended QA. Your task type determines the metric family. For supervised tasks, also decide on your split strategy — never eval on training data.
2
Prepare Eval Dataset
Curate a held-out test set — never tuned on, never seen. Aim for 200–2,000 examples covering failure modes, edge cases, and the full distribution you care about. Check for contamination with your training data.
3
Run Inference
Generate model outputs for every eval example. Use deterministic settings (temperature=0 or fixed seed) so results are reproducible. Log inputs, outputs, and metadata (model version, timestamp) in a structured format.
4
Compute Metrics
Use HuggingFace evaluate, sacrebleu, or bert-score — don't hand-roll BLEU. For LLM-as-judge, structure the prompt with explicit rubrics and parse the scores programmatically.
5
Error Analysis
Metrics alone don't tell you what to fix. Manually review the worst 20–50 examples. Cluster failures by type. The pattern you find here drives your next training decision more than any aggregate number.
6
Log & Track
Log every run with W&B, MLflow, or similar. Store the metric, model checkpoint, eval dataset version, and hyperparameters. Reproducibility is a prerequisite for improvement — if you can't reproduce a result, you can't build on it.

from evaluate import load
from transformers import pipeline

# Load model + metrics
clf = pipeline("text-classification",
               model="your-fine-tuned-model")
f1  = load("f1")
acc = load("accuracy")

predictions, references = [], []

for example in eval_dataset:
    out = clf(example["text"])[0]
    predictions.append(
        1 if out["label"] == "POSITIVE" else 0
    )
    references.append(example["label"])

# Compute all at once
results = {
    "f1": f1.compute(
        predictions=predictions,
        references=references,
        average="macro"
    ),
    "accuracy": acc.compute(
        predictions=predictions,
        references=references
    ),
}
print(results)

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

model_id = "your-model-id"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(
    model_id, device_map="auto"
)

def perplexity(text: str) -> float:
    inputs = tokenizer(
        text, return_tensors="pt"
    ).to(model.device)
    with torch.no_grad():
        loss = model(**inputs, labels=inputs["input_ids"]).loss
    return torch.exp(loss).item()

# Lower = more fluent / in-distribution
print(perplexity("The model explains the data well."))

    predictions=["text1", "text2"]
)
print(scores["mean_perplexity"])

from openai import OpenAI
import json

client = OpenAI()

JUDGE_PROMPT = """
You are an expert evaluator. Score the response on:
1. Accuracy (1-5)
2. Clarity (1-5)
3. Completeness (1-5)

Question: {question}
Response: {response}

Return JSON only: {{"scores": {{"accuracy": N, "clarity": N,
"completeness": N}}, "rationale": "..."}}
"""

def judge(question: str, response: str) -> dict:
    prompt = JUDGE_PROMPT.format(
        question=question, response=response
    )
    out = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        temperature=0,        # deterministic
        response_format={"type": "json_object"}
    )
    return json.loads(out.choices[0].message.content)

# Aggregate win rates
def win_rate(questions, model_a_resps, model_b_resps):
    wins = 0
    for q, a, b in zip(questions, model_a_resps, model_b_resps):
        sa = judge(q, a)["scores"]
        sb = judge(q, b)["scores"]
        score_a = sum(sa.values())
        score_b = sum(sb.values())
        if score_a > score_b: wins += 1
    return wins / len(questions)
Quick Reference

Eval Cheat Sheet

The practical rules for picking and running evals in production ML.

Picking Your Metric

›Classification + balanced → Accuracy
›Classification + imbalanced → F1 (macro)
›Summarization → ROUGE-L + BERTScore
›Translation → BLEU / METEOR / ChrF
›Code generation → Pass@k (HumanEval style)
›Open-ended → LLM-as-judge win rate

Eval Dataset Rules

›Never eval on training data — ever
›Check for contamination before benchmarking
›Cover edge cases, not just the easy distribution
›Version your eval set like your model
›200+ examples for reliable signal; 1,000+ for slicing

LLM Judge Tips

›Use rubrics — "score 1–5 on X" beats "which is better"
›Ask for chain-of-thought before the score
›Swap A/B order and average to cancel position bias
›Don't use the same model to judge itself
›Parse JSON scores programmatically — don't parse prose

Perplexity Rules

›Lower perplexity = more fluent, more in-distribution
›Compare only on same tokenizer and context length
›Watch for perplexity ≠ quality in instruction-tuned models
›Useful for domain shift detection

Benchmark Gotchas

›Benchmark saturation: scores keep rising, real capability lags
›Data contamination: if test set was in pretraining, scores lie
›Prompt sensitivity: MMLU score varies ±5% with phrasing
›Always report few-shot settings (0-shot vs 5-shot differ widely)

Key Libraries

›evaluate — HF unified metric API
›lm-evaluation-harness — EleutherAI benchmarks
›bert-score — contextual similarity
›sacrebleu — reproducible BLEU
›wandb — eval tracking + dashboards
